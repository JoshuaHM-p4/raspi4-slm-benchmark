# Results

Everything behind the report is committed. Nothing under `raw/` or the scoring folders is edited after it is written; integrity of every file is recorded in `SHA256SUMS` (verify from the repository root with `sha256sum -c results/SHA256SUMS`).

| Path | Contents |
| --- | --- |
| `raw/environment-*.json` | Board and OS snapshot (`scripts/capture_environment.py`) |
| `raw/build/` | llama.cpp build logs: the failed first build (prebuilt web-UI asset error) and the successful rebuild |
| `raw/feasibility/<label>-rN/` | Feasibility gate runs: server log, 1 Hz telemetry, rendered prompt, request/response, `result.json` |
| `raw/pilot/<label>/` | Phase 4 pilot: short llama-bench run and the two non-scored pilot prompts (greedy) |
| `raw/speed/<label>/` | Measured llama-bench session: `bench/` (warm-up, measured JSONL, GNU time), telemetry, start/end temperature and throttle flags |
| `raw/quality/<label>/` | Greedy answers to the 20 frozen prompts: per-answer request, rendered prompt, response, status, wall time; server log; telemetry |
| `raw/diagnostic/` | Labelled diagnostic runs that are not part of the comparison (Qwen with `--cache-ram 0`) |
| `raw/pilot-vendor/`, `raw/quality-vendor/` | Follow-up with each vendor's recommended sampling, seed 42 (`configs/vendor_sampling.json`) |
| `scoring/` | Greedy set, blinded: `blind_sheet.md` (what the scorer saw), `key.csv` (code → model), `blind_scores.as-saved.csv` (first blind pass, codes as mangled by the spreadsheet), `blind_scores.final.csv` / `blind_scores.csv` (final two-dimensional scores, codes restored) |
| `scoring-vendor/` | Same, for the vendor-sampling set |
| `processed/` | Curated tables regenerated by `python3 scripts/process_results.py` |

Absolute paths inside raw files (`/home/bagwis/...`) are the Pi's paths at run time.
